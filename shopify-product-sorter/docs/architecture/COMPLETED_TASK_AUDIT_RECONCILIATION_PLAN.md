## 8. Risks and rollback strategy

- **Risk — fabricated evidence:** never invent an implementation SHA that did not exist. Where the original implementation commit is unknown (the 18 validation_pending tasks and the 9 `78975ca` file associations), record only the true containing commit and mark it as a repair/durable commit.
- **Risk — clean-validation failure:** moving a task to `validation_pending` requires re-running the full suite in a detached clean worktree; if that fails, keep the task in `validation_pending` (or `blocked` with reason), never re-mark completed.
- **Risk — secret exposure:** SAFE-005 evidence is an encrypted archive; validation must not require decrypting or retaining the passphrase.
- **Risk — dirty-worktree contamination:** Phase 3B validation must run from a detached worktree at the Phase 3B commit, not the dirty main worktree.
- **Rollback:** the ledger hash chain makes history append-only; reverting a Phase 3B transition means appending a compensating transition, not rewriting. `git revert` of the Phase 3B commit restores `tasks.json`/`history.jsonl` to the Phase 3A state (statuses unchanged from the Phase 3A baseline).
- **Risk — untracked FE-008/BE-004/FE-004 files:** these files remain untracked at HEAD; Phase 3B must commit them (with evidence) before validation. If they are not intended for commit, the tasks must stay `validation_pending`/`implemented` and the declared files corrected.
